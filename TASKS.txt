# This file contains a list of the tasks implemented by SWE agents - numbered task0, task1, task2, etc.
# Each new task should just increment the task number.
# The current task types are: 
#   - task: any general task to be implemented with code or through command(s)
#   - issue: anything that needs to be resolved - e.g., bug
#   - decision: any decision that needs to be made - e.g., choosing a model
#
# This file contains the project tasks as YAML entries. Use the top-level `tasks` list.
# Each task should reference its parent feature and list any test IDs it owns.
# The validator script `src/validate_project_manifests.py` will enforce unique IDs and references.
#
# Important Note: dependencies field can be other tasks, OR external packages, libraries, frameworks - with the version - that need to be installed in order to complete the task 
#
# Template (YAML):
# tasks:
#   - id: taskX
#     title: Short title
#     type: Task type (defaults to "task" if omitted)
#     description: Short description of the work
#     files: [path/to/file1, path/to/file2]
#     steps:
#       - Step 1 description
#       - Step 2 description
#     dependencies: [taskZ, boto3]
#     tests: [test0, test1]
#     status: not-started / in-progress / etc
#
# A decision task has different fields:
#
# Template for decision tasks (YAML):
# tasks:
#   - id: taskX
#     title: Short title
#     type: decision
#     description: Description of the decision to be made. Can include some initial choices, if available.
#     options: Potential choices for the decision (e.g., choice of model), as a YAML style list. Populated once these are available.
#           - option1: overview/pros/cons/artifacts
#           - option2: overview/pros/cons/artifacts
#     criteria: list of measurable evaluation criteria (latency, accuracy, size, license)
#     selected_option: option id (set when status: approved)
#     rationale: short reasoning for selection.
#     approvals: list of approvers: human name / agent ID (optional)
#     status: not-started / in-progress / etc
#
# Examples:
# tasks:
#   - id: task0
#     title: Add capture button to camera view
#     type: task
#     description: Add a white capture button centered at the bottom of the camera view and wire it to the capture action.
#     files: [Sources/Views/CameraView.swift]
#     steps:
#       - step1: Add SwiftUI button centered at the bottom of the camera view
#       - step2: Wire button action to `CameraViewModel.capturePhoto()`
#       - step3: Add unit/UI test verifying the button triggers the capture action
#     dependencies: []
#     tests: [test0]
#     status: not-started
#
#   - id: task10
#     title: Select CoreML model for waste classification
#     type: decision
#     description: Evaluate candidate CoreML models for on-device inference and choose one.
#     options:
#       - id: option1
#         name: MobileNetV2-quant
#         summary: Lightweight MobileNetV2 quantized
#         pros: [small size, fast inference]
#         cons: [lower accuracy on electronics class]
#         artifacts: [s3://models/mobilenetv2-quant.mlmodel]
#       - id: option2
#         name: EfficientNet-lite
#         summary: Better accuracy, slightly larger
#         pros: [higher accuracy]
#         cons: [bigger binary]
#         artifacts: [s3://models/efficientnet-lite.mlmodel]
#     criteria:
#       - latency_ms: "<=200"
#       - accuracy_top1: ">=0.80"
#       - size_mb: "<=20"
#     selected_option: option1
#     rationale: smaller size and faster inference time
#     approvals: []
#     status: completed

  - id: task117
    title: "RegexInputGuard — comprehensive injection pattern library"
    type: task
    description: |
      Implement the full `RegexInputGuard` class in `src/kinnoo/input_guard.py` with
      comprehensive regex patterns for 6 threat categories. Each pattern is a tuple of
      (compiled_regex, threat_category, human_description). The guard supports type-aware
      checking: different input_type values activate different pattern subsets. The
      `check_inputs()` method aggregates results across multiple typed parameters for
      future parameterized input support (-e, -i, -d, -u flags).

      Threat categories and patterns to implement:

      **SQL Injection** (SQL_INJECTION):
      - UNION SELECT / UNION ALL SELECT
      - DROP TABLE / DROP DATABASE
      - INSERT INTO ... VALUES
      - DELETE FROM
      - Tautology: OR 1=1, OR '1'='1', OR ''='', AND 1=1
      - Comment injection: --, #, /* (as SQL comment starters following injection context)
      - WAITFOR DELAY (time-based blind SQLi)
      - EXEC xp_ (stored procedure injection)
      - Stacked queries: semicolon followed by SELECT/INSERT/UPDATE/DELETE/DROP

      **Shell Injection** (SHELL_INJECTION):
      - Command chaining: ; & | && || followed by dangerous commands (rm, cat, wget, curl,
        sudo, sh, bash, python, chmod, chown, nc, ncat, mkfifo, dd, kill)
      - Command substitution: $(...) and backtick `...`
      - Pipe to shell: | sh, | bash, | /bin/sh, | /bin/bash
      - Input/output redirection: > /etc/, >> /etc/, < /etc/
      - Null byte injection: \x00, %00

      **Path Traversal** (PATH_TRAVERSAL):
      - ../ and ..\ sequences (2+ levels)
      - URL-encoded variants: %2e%2e%2f, %2e%2e/, ..%2f
      - Double-encoding: %252e%252e%252f
      - Absolute sensitive paths: /etc/passwd, /etc/shadow, /proc/self, /dev/

      **SSRF** (SSRF):
      - Dangerous protocols: file://, gopher://, dict://, ldap://
      - Internal IPs: 127.0.0.1, 0.0.0.0, 10.x.x.x, 172.16-31.x.x, 192.168.x.x
      - IPv6 loopback: [::1], ::1 (as URL host)
      - localhost as hostname
      - Octal IP: 0177.0.0.1
      - AWS metadata endpoint: 169.254.169.254

      **XSS** (XSS):
      - <script tags (with variations like <ScRiPt, <script/src)
      - javascript: URI scheme
      - Event handlers: onerror=, onload=, onclick=, onmouseover=, onfocus=
      - Dangerous tags with event sources: <img, <iframe, <svg, <object, <embed
      - data:text/html

      **Template Injection** (TEMPLATE_INJECTION):
      - Jinja2/Twig: {{ and }}
      - ERB: <% and %>
      - Expression language: ${...}, #{...}

      **Type-aware input_type filtering:**
      - "text" or "string": all 6 categories
      - "file_path": PATH_TRAVERSAL + SHELL_INJECTION only
      - "url": SSRF + SHELL_INJECTION only
      - "id": SQL_INJECTION + SHELL_INJECTION + TEMPLATE_INJECTION only

      **check_inputs() multi-value aggregation:**
      - Iterate over (param_name, value, input_type) tuples
      - Call check(value, input_type) for each
      - Set param_name on each resulting InputWarning
      - Merge all warnings; safe = True only if all inputs are safe
