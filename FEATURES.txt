  - id: feature1
    title: Manifest schema and validation
    description: |
      Define the kinnoo.yaml manifest schema and implement a validator that parses
      and validates manifest files against it. The validator returns clear, actionable
      error messages and is usable as a library function for other commands (pack, run, etc.).

      Schema definition:
      | Field              | Required | Type         | Constraints                                      |
      |--------------------|----------|--------------|--------------------------------------------------|
      | name               | yes      | string       | non-empty, valid package name (alphanumeric, -)  |
      | version            | yes      | string       | valid semver (e.g., "0.1.0", "1.2.3")            |
      | entrypoint         | yes      | string       | non-empty file path                              |
      | runtime.language   | yes      | string       | e.g., "python"                                   |
      | runtime.version    | yes      | string       | version constraint (e.g., ">=3.10")              |
      | runtime.type       | yes      | string       | e.g., "one-shot"                                 |
      | dependencies       | yes      | list[string] | can be empty list                                |
      | inputs.type        | yes      | string       | e.g., "text"                                     |
      | outputs.type       | yes      | string       | e.g., "text"                                     |
      | framework          | no       | string       | optional, e.g., "langchain"                      |
    tasks: [task0, task1, task2, task3]
    acceptance_criteria:
      - id: AC1
        description: A kinnoo.yaml with all required fields and valid values passes validation without errors.
      - id: AC2
        description: Missing any required field (name, version, entrypoint, runtime.language, runtime.version, runtime.type, dependencies, inputs.type, outputs.type) produces a specific error naming the missing field.
      - id: AC3
        description: Invalid field types (e.g., version as number, dependencies as string) produce a specific error describing the type mismatch.
      - id: AC4
        description: Invalid semver format in version field produces a descriptive error.
      - id: AC5
        description: "The validator is callable as a Python function that returns (is_valid: bool, errors: list[str])."
      - id: AC6
        description: Optional field 'framework' is accepted when present, ignored when absent.
      - id: AC7
        description: runtime.type set to any value other than "one-shot" produces a descriptive error stating it is not supported in this version.

  - id: feature3
    title: "kinnoo run (local) — Agent execution from source"
    description: |
      Implement the `kinnoo run` CLI command that executes an agent from a local
      directory. This is the core runtime contract: validate manifest, set up
      environment, install dependencies, and execute the entrypoint.

      Execution flow:
      1. Validate kinnoo.yaml using feature1 validator
      2. Create Python virtual environment (if not exists)
      3. Install dependencies from requirements.txt
      4. Execute entrypoint with user-provided input: `python run.py "<input>"`
      5. Stream stdout/stderr to terminal
      6. Return exit code from entrypoint

      Usage: `kinnoo run <path> "<input>"`
      Example: `kinnoo run ./my-agent "Hello, agent!"`
    tasks: [task7, task8, task9, task10, task11, task12, task13, task14]
    acceptance_criteria:
      - id: AC1
        description: "Running `kinnoo run ./my-agent \"test\"` on a valid agent directory executes the entrypoint and prints output."
      - id: AC2
        description: "Invalid or missing kinnoo.yaml produces clear validation errors from feature1 validator before execution."
      - id: AC3
        description: "A Python venv is created in `<agent-dir>/.venv/` if it does not exist."
      - id: AC4
        description: "Dependencies from requirements.txt are installed into the venv before execution."
      - id: AC5
        description: "The entrypoint receives the input string as the first CLI argument (sys.argv[1])."
      - id: AC6
        description: "Stdout and stderr from the entrypoint are streamed to the terminal in real-time."
      - id: AC7
        description: "Non-zero exit codes from the entrypoint are propagated to the kinnoo process exit code."
      - id: AC8
        description: "Running `kinnoo run` without arguments prints usage: `Usage: kinnoo run <path> \"<input>\"`."
      - id: AC9
        description: "Missing entrypoint file (as declared in manifest) produces a clear error before execution."
    notes:
      - "Uses feature1 validator — reuse existing validation, single source of truth"
      - "Venv created inside agent directory (.venv/) for isolation without Docker overhead"
      - "Real-time streaming provides developer-friendly UX during agent execution"
      - "Exit code propagation enables composability with shell scripts and CI pipelines"
      - "Fail-fast on missing entrypoint — check before venv setup to save time"
      - "Framework-agnostic execution: blindly runs entrypoint per MVP black-box philosophy"
      - "No --docker or --remote flags in MVP — escape hatches deferred to V1.1/V2"
      - "Preflight checks (tools, services, GPU) deferred to future feature per roadmap"
    owner: techlead-agent
    dependencies: [feature1]
    status: completed
