# task523 implementation notes

- `scripts/ops/build_and_push_lambda_security_check_image.sh` is now environment-aware (`--env dev|prod` or `ENVIRONMENT=...`). It runs `terraform init -reconfigure -backend-config=environments/<env>/backend.hcl` against the selected environment's state and reads `terraform output lambda_security_check_ecr_repository_url`, so the same script can bootstrap either Dev or Prod without code change. Defensive cross-env guard refuses to operate when the resolved ECR URI is dev-scoped under `--env prod` (and vice versa). `--dry-run` shows exactly which image URI would be produced and what tfvars line to paste.
- The chicken-and-egg bootstrap procedure is documented in the script header and called out in the prod runbook (Phase 3): targeted apply against `module.ecr` first using the `000000000000.dkr.ecr...` placeholder URI from `iac/environments/prod/terraform.tfvars`, then run this script, then paste the real URI back into the prod tfvars and run a full apply.
- Test coverage: `tests/iac/test_feature121_lambda_bootstrap.py` (test746) verifies the documented `-target=module.ecr` trick is mentioned, that the script supports `--env`, that dry-run against `--env prod` emits a prod-scoped ECR URI, and that dev mode does not silently emit prod targets.
