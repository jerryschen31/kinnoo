# task519 implementation notes

- `scripts/ops/rebuild_push_server_and_redeploy_ecs.sh`: removed the hardcoded `kinnoo-dev-cluster` / `kinnoo-dev-service` literals and the hardcoded `AWS_PROFILE=jerry`. Script now takes `--env dev|prod` (or `ENVIRONMENT=...`), runs `terraform init -reconfigure -backend-config=environments/<env>/backend.hcl`, and resolves `ecr_repository_url` / `ecs_cluster_arn` / `ecs_service_name` from terraform outputs. Adds a defensive guard that refuses to push when the resolved targets look cross-environment (e.g., `kinnoo-dev-*` while `--env prod`). Supports `--dry-run` for safe verification.
- `scripts/ops/build_and_push_lambda_security_check_image.sh`: same env selector; supports `--dry-run` and same cross-env guard. Initializes against the requested env's backend so `terraform output lambda_security_check_ecr_repository_url` returns the right repo. Print line at the end now references `iac/environments/<env>/terraform.tfvars`.
- `scripts/ops/check_cloudflare_dns_setup.sh`: parameterized by `ENVIRONMENT`/`FRONTEND_SUBDOMAIN`/`API_SUBDOMAIN`/`BASE_DOMAIN`. Defaults remain dev so existing dev workflows are unchanged. Adds an additional best-effort `GET https://${API_FQDN}/health` health gate (must return 200).
- `tests/iac/test_feature121_ops_scripts.py` (test742): static + dry-run subprocess assertions covering both directions of the dev/prod safety guard.
